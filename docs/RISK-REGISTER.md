# Risk Register

Expanded from PRD §16. Each risk records likelihood/impact (qualitative), the mitigation **as implemented or planned**, an owner phase, and its current status. Reviewed at every phase gate; new evidence updates this file rather than hallway memory.

| ID | Risk | Likelihood | Impact | Mitigation | Phase | Status |
|---|---|---|---|---|---|---|
| R-01 | SMTP port 25 blocked by the hosting provider | **Certain in the build sandbox; high generally** | Deep mode cannot work at all | Phase 0 hard gate (PRD §6); Deep ships disabled behind two flags (`SMTP_DEEP_ENABLED`, `SMTP_EGRESS_APPROVED`); Quick mode is the launch product; deployment shortlist (Hetzner/Vultr/AWS EC2) with documented approval steps in `phase-0-audit.md` | 0, 5 | **Realised in sandbox — BLOCKED, handled as designed** |
| R-02 | Recipient servers hide mailbox state (accept-all, deferred DATA-stage rejection) | High | High unknown rate; false "valid" claims if handled naively | Conservative statuses (ADR-005); `provider_defers_recipient_validation` → `unknown`; never issue DATA to force an answer; `valid` requires SMTP acceptance **and** a conclusive catch-all check, else `likely_valid` + `catch_all_unchecked` | 3, 5 | Mitigated by design |
| R-03 | Anti-abuse systems block/score the probe IP | Medium (once Deep exists) | Reduced coverage, rising unknowns | Stable static egress IP, PTR/rDNS + SPF on a controlled probe domain, strict per-domain/per-MX concurrency + cooldowns, `unknown_rate` alerting by provider family | 5, 8 | Deferred with Deep |
| R-04 | SMTP probing viewed as abusive; provider termination or complaints | Medium | Account loss, reputational harm | No DATA ever (automated test asserts this); no VRFY/EXPN enumeration; one synthetic catch-all recipient per domain per 24 h max; authenticated-only API with daily limits; published acceptable-use terms; runbook `smtp-block.md` | 5, 8 | Deferred with Deep; runbook written |
| R-05 | Disposable-domain dataset goes stale | High over time | Missed temporary domains, `risky` under-detection | Versioned datasets with recorded source, licence, commit/version, import timestamp, and hash (PRD §4 Stage 2); scheduled refresh is P1 and must re-validate licence before ingest — never auto-ingest an unknown-licence dataset | 3, P1 | Mitigated for MVP dataset; refresh deferred |
| R-06 | False `invalid` from a generic SMTP 550 (policy rejection) | Medium | Customer deletes real contacts — direct data-loss harm | Only unambiguous definitive mailbox-not-found evidence (e.g. enhanced `5.1.1`) maps to `invalid`; generic 550 → `smtp_policy_rejected` → `unknown`; classification tests cover this case explicitly | 3, 5 | Mitigated by design + tests |
| R-07 | Cloud/operating cost exceeds credit revenue | Medium | Negative margin, unsustainable free tier | Meter everything (`credits_charged_total`, per-mode cost); conservative free grant (100/month provisional); concurrency caps; price only after benchmarks (Phase 9); **never** an unlimited lifetime plan | 8, 9 | Open — pricing is a hypothesis (PRD §9.2) |
| R-08 | Customer list exposure (breach, cross-tenant leak, log leakage) | Low | Severe trust/legal damage | AES-256-GCM encryption at rest + HMAC dedupe (ADR-007); tenant scoping on every query + cross-tenant tests; short retention (source 24 h, results 7 days) + immediate delete; no plaintext addresses in logs/queue payloads; key-compromise runbook | 2, 4, 8 | Mitigated; pen-test before launch (Phase 8) |
| R-09 | SSRF / DNS rebinding via MX resolution (SMTP worker induced to connect to internal addresses) | Medium (once Deep exists); DNS stage shares the resolver code path | Internal network/metadata access | Resolve-then-validate: block loopback/private/link-local/multicast/reserved/metadata IPs, re-checked immediately before connect (TOCTOU); never accept user-supplied host/port; fixture tests incl. rebinding simulation (PRD §13.4) | 3, 5 | IP blocklist implemented + unit-tested; connect-path checks land with Phase 5 |
| R-10 | CSV parser abuse (bombs, formula injection, memory exhaustion) | Medium | Worker OOM, poisoned exports opened in spreadsheets | Streaming parser with file-size/row-count caps (10,000 rows initial); uploads treated as data, never executed; exports escape leading `= + - @` and control chars (CSV formula-injection escaping, unit-tested) | 4 | Mitigated |
| R-11 | Double-charging after retries/restarts | Medium | Billing disputes, trust loss | Append-only ledger with unique idempotency keys (ADR-008); duplicates and `unknown` never charged; cancelled batches release reservations; restart/idempotency integration tests; ledger reconciliation alert | 4 | Mitigated by design + tests |
| R-12 | Competitor undercuts on price (Reoon from ~$11.90/10k) | High | Weak conversion | Compete on explainability, API ergonomics, and bulk reliability — not price (PRD §1.3); do not race to zero; validate willingness-to-pay in beta before fixing prices | 9 | Accepted, monitored |
| R-13 | Product name conflict ("MailCheckr" not cleared) | Unknown | Forced rebrand cost | Trademark + domain search **before** any public branding spend; treat the name as a working name until cleared (PRD header) | 8/9 | Open |
| R-14 | Compliance overclaiming (e.g. marketing "GDPR compliant" on the basis of encryption alone) | Medium | Legal exposure | No compliance claims in product copy; privacy notice/terms/DPA reviewed by counsel before public launch (PRD §10.2); data-minimisation and deletion controls implemented regardless | 7, 8 | Mitigated in copy; legal review open |
| R-15 | Dashboard JWT in `localStorage` is XSS-exfiltratable | Low–Medium | Session theft | Recorded trade-off (ADR-010): strict CSP, no third-party scripts on authenticated pages, 1 h token lifetime; migration to HttpOnly SameSite cookies + CSRF is a pre-launch follow-up | 7, 8 | **Open — accepted for closed beta only** |
| R-16 | Provider-wide behaviour changes (e.g. a major mailbox provider changes probe responses) | Medium over time | Sudden unknown/invalid-rate shifts misread as product bugs | `unknown_rate` and outcome metrics segmented by provider/domain family (PRD §12); benchmark suite on controlled mailboxes re-run on change; classification changes ship as versioned policy with changelog | 8 | Monitoring designed; baselines pending staging |
| R-17 | Sandbox/staging evidence mistaken for production evidence (e.g. synthetic DNS in the Muse VM) | Medium | False gate decisions | Phase 0 audit documents exactly which environment produced which evidence; gate script must run on the candidate host itself; TEST-REPORT marks environment per result | 0, 8 | Mitigated by documentation discipline |

## Review cadence

- Re-score likelihoods at each phase gate and after any incident.
- A risk whose mitigation depends on Deep SMTP (R-03, R-04) stays *Deferred with Deep* until ADR-006 is superseded by a passed gate.
